The workbench wraps a dockview editor in a VS Code-style frame: fixed chrome bands (header, status bar), an activity bar, primary and secondary side bars, and a tool panel. The editor in the centre is a full dockview instance, so tabs, splitting, floating groups, popout windows and edge groups all keep working inside it.

## Regions

A workbench is built from an outer grid of regions around the editor:

| Region | Description |
| --------------------- | ------------------------------------------------------------ |
| `header` | Fixed-height band pinned to the top. |
| `statusBar` | Fixed-height band pinned to the bottom. |
| `activityBar` | Fixed-width icon rail next to the primary side bar. |
| `primarySideBar` | Resizable side bar (VS Code's Explorer side). |
| `secondarySideBar` | Resizable side bar, always mounted opposite the primary. |
| `panel` | The tool panel (terminal / problems / output). |

Every region is optional. Each names a `component` that the workbench resolves through `createComponent`, the same contract used by gridview. The editor is always present.

## Creating a workbench

```ts
// JavaScript
const api = createWorkbench(element, {
    header: { component: 'header' },
    statusBar: { component: 'status' },
    activityBar: { component: 'activity' },
    primarySideBar: { component: 'explorer' },
    secondarySideBar: { component: 'outline' },
    panel: { component: 'terminal', position: 'bottom', alignment: 'center' },
    createComponent: (options) => {
        /* return a GridviewPanel for the bands / side bars / panel */
    },
    dockview: {
        // options for the embedded editor (theme, dnd, ...)
        createComponent: (options) => {
            /* return an IContentRenderer for the editor panels */
        },
    },
});

// the editor is a normal dockview
api.dockview.addPanel({ id: 'file.ts', component: 'editor', title: 'file.ts' });
```

In React, Vue and Angular the same regions are set as props / inputs. Bands, side bars and the panel come from a `components` map; the editor panels come from an `editorComponents` map.

## Side bar side

The primary side bar and the activity bar move together and can sit on either side. The secondary side bar always mirrors to the opposite side. Flip them at runtime:

```ts
api.setPrimarySideBarPosition('right'); // activity bar follows; secondary mirrors
const side = api.primarySideBarPosition; // 'left' | 'right'
```

Set the starting side with the `primarySideBarPosition` option.

Flipping normally just moves the side bars, preserving their widths and contents. The exception is when a tool panel currently sits in the body — a top/bottom panel with `center`, `left` or `right` alignment, or a `left`/`right` panel — where the flip re-places the panel against the mirrored side bars and the side bar components are re-created (their content re-initialises). A `justify` panel or no panel flips without re-creating anything.

## Activity bar and view containers

The activity bar selects which view the primary side bar shows. The workbench tracks an active view container id and fires an event when it changes; the side bar component renders the selected view.

```ts
// an activity-bar item was clicked
api.setActiveViewContainer('search'); // reveals the side bar if hidden

// clicking the already-active item again toggles the side bar shut
api.setActiveViewContainer('search');

const active = api.activeViewContainer; // 'search'

api.onDidChangeActiveViewContainer((id) => {
    // swap the primary side bar content to the view for `id`
});
```

Set the initial view with the `activeViewContainer` option. The active view container is serialized.

## Panel position and alignment

The tool panel can sit on any side of the editor, and a top or bottom panel can span either the editor column or the full width.

- `position`: `'bottom'` (default), `'top'`, `'left'` or `'right'`.
- `alignment` (top / bottom only):
  - `'center'` spans the editor column so the side bars run full height beside the panel.
  - `'justify'` spans the full width so the side bars stop above it.
  - `'left'` spans the editor plus the side bars to its left; the right side bar stays full height.
  - `'right'` spans the editor plus the side bars to its right; the left side bars stay full height.

```ts
api.setPanelPosition('right');
api.setPanelAlignment('justify');
```

## Visibility

Every region can be shown or hidden, which redistributes the space to the editor:

```ts
api.setHeaderVisible(false);
api.togglePrimarySideBar();
api.toggleSecondarySideBar();
api.togglePanel();
api.setActivityBarVisible(false);
```

## Theming

Each region's container carries a class (`dv-workbench-header`, `dv-workbench-activity-bar`, `dv-workbench-primary-side-bar`, `dv-workbench-panel`, and so on), and the workbench root carries `dv-workbench`. The bundled stylesheet gives these a themed surface derived from the active dockview theme, so a band component that sets no background of its own sits on the right colour automatically. Pass the theme class through the workbench `className` (React/Vue/Angular) so the tokens resolve:

```tsx
<WorkbenchReact className="dockview-theme-abyss" ... />
```

Restyle any region by overriding its token:

```css
.dv-workbench {
    --dv-workbench-surface-background-color: #1e1e1e;
    --dv-workbench-band-background-color: #333;
    --dv-workbench-foreground-color: #ddd;
    --dv-workbench-border: 1px solid #000;
}
```

## Serialization

`api.toJSON()` captures the outer grid (region sizes and visibility), the side bar side, the panel position and alignment, and the embedded dockview state (edge groups included). `api.fromJSON(state)` restores all of it.
